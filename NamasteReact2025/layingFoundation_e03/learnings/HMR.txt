🔌 How Does WebSocket Help with HMR?
1️⃣ WebSocket Connection is Established
When you start your development server (npm start or npm run dev), Vite or Webpack DevServer automatically creates a WebSocket connection between your browser and the server.
You can check this in DevTools → Network Tab → WS (WebSocket) Tab.
Example WebSocket URLs:
Vite HMR WebSocket:
ws://localhost:5173/

Webpack DevServer WebSocket (HMR):
ws://localhost:3000/sockjs-node

2️⃣ Detecting File Changes
When you change a file (e.g., App.js), the development server detects the change.
It then compiles only the modified file instead of rebuilding the entire project.
3️⃣ Sending Updates via WebSocket
Instead of forcing a full-page reload, the server sends an update through the WebSocket connection.
The frontend receives the update and replaces only the changed module dynamically.
4️⃣ Injecting New Code into the Running App
The updated JavaScript file is injected into the browser without reloading the page.
This helps preserve the application state (e.g., form inputs, animations, etc.).
🔍 Example: Vite HMR WebSocket Flow
Let’s say you are running a Vite-powered React app and you change App.jsx:

WebSocket Connection:
When the browser loads http://localhost:5173, Vite establishes a WebSocket connection:

ws://localhost:5173/
File Change Detection:
You modify App.jsx.
Vite detects the change and doesn’t reload the entire app.
Patching Only the Updated Code:
Vite sends the updated App.jsx code through the WebSocket.
The React app replaces the old component without a full reload.

State is Preserved:
If you were typing something in an input field, the text does not disappear because the app didn’t reload.



🚀 Benefits of HMR
✅ Faster development (no full reload).
✅ Preserves UI state (e.g., form inputs, animations).
✅ Improves developer experience (instant feedback).

🚀 Why is This So Powerful?
✅ No full reload → Saves time and speeds up development.
✅ State is preserved → No lost form inputs, scroll position, or animations.
✅ WebSocket-powered updates → The frontend gets only the necessary changes





How HMR Works Internally?
Step-by-Step Flow:
1️⃣ File Watcher

Parcel/Webpack watches your project files (fs.watch in Node.js).
If a file is changed, it triggers a rebuild only for that file.
2️⃣ Build Incremental Update

Instead of rebuilding the whole app, it only recompiles the changed file.
3️⃣ Send Update via WebSocket

The dev server pushes an update to the browser through WebSocket (ws://localhost:3000).
4️⃣ Replace Old Code in Browser

JavaScript executes the new module without reloading the page.
For React, React Fast Refresh re-renders components with updated code while preserving state.
